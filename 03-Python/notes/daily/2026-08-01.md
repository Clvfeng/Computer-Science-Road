## 学习内容

### 结构体指针成员
- struct Node { int data; Node* next; }：next 存的是下一个节点的地址
- 通过指针访问成员用 ->：a.next->data 等价于 (*a.next).data
- . 用在对象上（a.data），-> 用在指针上（a.next->data）

### nullptr
- 空指针：不指向任何地方
- 在链表里当终点标记：while (cur != nullptr) 靠它停下来

### 链表遍历模板
Node* cur = head;
while (cur != nullptr) {
    cout << cur->data << " ";
    cur = cur->next;
}

### 数组 vs 链表（概念）
- 数组：内存连续，按下标访问快，插入/删除要搬动元素
- 链表：节点用指针串联，插入/删除只改指针，但不能按下标直接访问

### 头插法
- 新节点->next = head; 再 head = 新节点（先连后面，再改 head）
- 参数用 Node*& head（引用）：不传引用改不到 main 里的 head

### 栈 vs 堆（今天最重要）
- Node _new; = 栈上局部变量，函数一结束就销毁
- Node* p = new Node; = 堆上分配，函数结束后仍存活，要 delete 释放
- new 和 delete 成对出现，否则内存泄漏
- 局部变量地址被指针记住 = 悬垂指针（指向已失效内存）

### 删除节点（双指针 prev/cur）
- 单向链表不能回头，用 prev 记住前一个节点
- prev->next = cur->next; delete cur;（跳过并释放）
- 删除头节点是特例：head = head->next; delete 旧头; 然后 return（删头后必须立即结束）

### 指针赋值心法
- 指针 = 装"门牌号"（地址）的盒子
- p = q; → 让 p 和 q 指向同一个地方（改贴纸）
- *p = *q; → 复制内容（改值）
- 指针赋值 = 搬门牌号，不是搬数据

## 遇到的问题

### 1. 链表节点忘记连接 → 程序崩溃
- 问题：创建了 3 个节点并赋值，但忘了写 a.next=&b; b.next=&c; c.next=nullptr;
- 现象：编译通过，运行直接崩，退出码 -1073741819（内存访问错误）
- 原因：a.next 未初始化 = 野指针，循环遍历到垃圾地址 → 崩
- 解决：显式连接 3 个节点，最后一个指向 nullptr
- 收获：未初始化的指针编译不报错，一跑就崩；看退出码能判断是内存问题

### 2. 头插法死循环
- 原因：Node _new; 是栈上临时变量，函数结束销毁后 head 指向失效内存（悬垂指针）
- 三次调用复用同一栈地址 → 节点自己指向自己 → while 永远到不了 nullptr
- 解决：改用 new 在堆上分配节点

### 3. 删除头节点后忘了 return
- 原因：删完头节点继续执行情况 2，逻辑混乱
- 解决：删头是独立操作，完成后立即 return

### 4. 指针赋值一度混淆
- 解决：建立"贴纸/门牌号"模型，区分改贴纸（p=q）和改内容（*p=*q）

### 5. VS Code 集成终端无法启动（退出码 -1）
- 问题：重装 VS Code、重置配置后仍未解决
- 解决：暂用外部 PowerShell + run.ps1 编译运行（已验证可用）

## 今天理解最重要的一点
链表的灵魂是"连接"：每个节点的 next 必须显式指向下一个节点，最后一个指向 nullptr 作为终点。new 出来的东西才"活得过函数"；栈上临时变量 + 指针 = 悬垂指针。指针赋值搬的是门牌号，不是数据。
