## 学习内容

### 排序 + 贪心（活动选择类）

- **贪心的判据是「结束时间最早的」**，不是开始时间最早的 —— 一件事结束得越早，后面能塞进去的越多
- 反例（为什么不能按开始时间排）：`(1,10) (2,3) (3,4)` 按开始排第一个就选 `(1,10)`，答案 1；正确答案 2
- 「前一个结束的瞬间可以开始下一个」→ 判断用 `>=` 而不是 `>`
- **元组打包是关键手艺**：`acts.append((et, st))` 再 `acts.sort()`，元组整体搬动、永远不会被拆散，不需要两个平行列表
- 扫描时维护 `last_end`，初值 `-1`（"还没选过"的标记，跟二分里 `first = -1` 是同一手法）

### 模拟的状态变量（排队类）

- **不要模拟时间流逝，只维护一个状态变量**：窗口什么时候空出来
- `start = max(t, free_at)` 一行代替整个 if：来的时候空着 → 取 `t`；还没空 → 取 `free_at`
- 更新 `free_at = start + w`；n = 10 万也不怕，O(n)
- 「窗口状态交替」是错的想法：可能连着好几个人都在排队，两态 flag 装不下

### 元组 vs 列表（Day4 旧知识，已生疏）

- `[]` 能改（`a[0]=9` / `append` / `sort`），`()` 不能改，也没有 `.sort()`
- 分界线：**长度会变 / 要增删改 → 列表；几个数永远绑在一起当一条记录 → 元组**
- 这题的正确搭配：**外层列表**（要 append + sort），**里面每条是元组**
